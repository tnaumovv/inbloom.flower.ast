# Проверка In Bloom

Дата: 18 октября 2026 года. Проверялась первая версия по утверждённому макету v3.

## Среда и результаты

- Node.js 24.22.0, Next.js 16.4.2, Chromium 156 через Playwright 1.64.1.
- Production-сборка: `npm run build`; сервер `npm run start -- --hostname 127.0.0.1 --port 3001`.
- Проверяемый адрес: `http://127.0.0.1:3001`. Это локальный preview, сайт на хостинге не опубликован.
- `npm test`: 2 файла, 8 тестов прошли.
- `npm run typecheck`, `npm run lint`, `npm run build` и `git diff --check`: успешно.
- `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3001 npm run test:e2e`: 4 файла, 15 сценариев прошли.

## Проверенные сценарии

- Витрина содержит четыре букета с названиями и ценами из сохранённых материалов. Декодированный текст каждого WhatsApp URL соответствует выбранному товару; общий запрос и индивидуальная композиция используют отдельные сообщения.
- Якоря ведут к реальным секциям. Телефон, полный каталог, 2ГИС и Instagram имеют ожидаемые адреса. Внешние ссылки новой вкладки содержат `noopener noreferrer`. Сообщения в WhatsApp не отправлялись.
- На desktop карточки расположены в одном ряду. На мобильном работают стрелки, Home/End и ArrowLeft/ArrowRight, ручная горизонтальная прокрутка, границы списка и изменение ширины 390 → 1440 → 390 px.
- Мобильное меню доступно с клавиатуры, закрывается после выбора, по Escape с возвратом фокуса и при переходе на desktop.
- Reduced motion проверен до загрузки и при смене настройки после загрузки. Автоматического перелистывания нет.
- Viewport 360×844, 390×844, 768×844 и 1440×1000: изображения загружаются, общего горизонтального переполнения нет. Обработчики ошибок подключены до перехода на страницу; `pageerror`, `console.error`, `console.warn` не обнаружены.
- Без JavaScript в серверном HTML доступны четыре товара, ссылки заказа и нативное мобильное меню. При блокировке изображений сохраняются название, цена, ссылка и геометрия карточки.
- Проверены русский язык документа, title, description, Open Graph, единственный h1 и видимая ссылка пропуска навигации с клавиатуры. Canonical не задан без публичного домена; настройка `SITE_URL` описана в README.

## Визуальная проверка

Полные снимки 1440 и 390 px просмотрены и сопоставлены с v3: последовательность секций, масштаб цветочных композиций, оливково-кремовая палитра, коралловые действия, растительные переходы и читаемость текста. Текст и кнопки реализованы HTML, декоративные изображения не содержат интерфейсных надписей. Проверены видимые focus-состояния и основные зоны нажатия около 44 px.

Фактические снимки сохраняются тестами в игнорируемую папку `.frontend-workbench/inbloom-runtime/`:

- `desktop.png` — вся страница при 1440×1000.
- `mobile.png` — вся страница при 390×844, первая карточка после возврата Home и завершения прокрутки.
- `preview.png` — первый экран при 1440×1000.

## Ограничения

Физический touch-жест и реальные устройства iOS/Android не проверялись; горизонтальная прокрутка и адаптивность проверены в Chromium. Safari, Firefox, screen reader и полный аудит WCAG не проводились. Снимки не являются автоматическим pixel-diff тестом.

Товарные вырезки демонстрационные; перед коммерческой публикацией нужно подтвердить данные и права на материалы у владельца. Происхождение изображений и лицензии шрифтов перечислены в README и `docs/assets/`.

`npm audit --omit=dev` не выявил уязвимостей. Полный audit сообщает пять high-записей в цепочке ESLint → braces; исправленной upstream-версии нет на дату проверки. Подробности и ссылка на advisory находятся в README. Автоматический downgrade Next.js ESLint-конфига не применялся.

Независимое ревью всей реализации выполняется после фиксации этой версии; его результат будет добавлен сюда отдельно.
