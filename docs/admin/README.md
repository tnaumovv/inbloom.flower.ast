# Админка In Bloom

Адрес: `https://ваш-домен.kz/admin`. Отдельная БД не используется: букеты хранятся в существующей Google Таблице, фотографии — в Cloudinary, доступ проверяется через Google. Без полной настройки админка блокирует редактирование; демонстрационных сохранений в production нет.

## Для флориста с телефона

1. Откройте `/admin` и нажмите кнопку входа через Google. Выберите аккаунт, которому владелец разрешил доступ.
2. Нажмите **Добавить букет**, выберите фото из галереи или сделайте снимок через меню телефона.
3. Введите название и целую цену в тенге. Описание, состав, категорию и порядок можно заполнить дополнительно.
4. Нажмите **Опубликовать** или **Сохранить скрытым**. Дождитесь подтверждения. Открытая витрина получает изменения при следующем обновлении каталога; безусловного срока при сбое сети нет.
5. Для правки нажмите на существующий букет. **Скрыть** убирает его с витрины, сохраняя в админке и таблице; **Показать** возвращает. Окончательного удаления здесь нет.

Фото: JPG, PNG, WebP и передача HEIC/HEIF для преобразования в WebP; исходный файл до 10 МБ, итоговая сторона до 2000 px. Живую совместимость HEIC конкретного телефона и настроенного Cloudinary нужно проверить до передачи владельцу. Неподходящий снимок можно пересохранить как JPG.

При ошибке сохранения текст и выбранное фото остаются в открытой форме. Повторяйте сохранение в ней — ID остаётся прежним. Подтверждённое фото не загружается заново при обычном повторе. Если истёк вход, откройте вход в новой вкладке, затем вернитесь к форме; при ошибке подтверждения фото выберите его ещё раз. При конфликте правок откройте букет заново, сначала скопировав свой несохранённый текст.

Сессия действует 8 часов. Владелец добавляет/убирает адреса в `ADMIN_EMAILS`; удалённый адрес теряет доступ при следующем защищённом запросе. Смена секрета сессии завершает все входы.

## Однократная настройка Google

Используйте Google Cloud проект, который останется у компании.

1. Включите Google Sheets API. Существующий серверный ключ чтения каталога сохраняется.
2. Настройте экран согласия OAuth для приложения In Bloom и создайте OAuth client типа **Web application**. Для входа используются Google Identity Services и базовый профиль, без запроса прав на личные таблицы флористов.
3. В **Authorized JavaScript origins** добавьте точный origin сайта, например `https://example.kz`. Для разработки отдельно добавьте `http://localhost:3000` или фактический локальный адрес/порт. Для popup-входа GIS отдельный redirect URI не используется.
4. Запишите client ID в `ADMIN_GOOGLE_CLIENT_ID`, разрешённые адреса через запятую — в `ADMIN_EMAILS`. Используйте контролируемые компанией Gmail/Google Workspace аккаунты. Если Google-приложение находится в тестовом режиме, добавьте нужные аккаунты в доступные тестовые пользователи по требованиям консоли.
5. Создайте сервисный аккаунт для каталога и JSON-ключ. Выдавать ему роль владельца Google Cloud проекта не нужно.
6. Откройте текущую таблицу и поделитесь **только этой таблицей** с `client_email` сервисного аккаунта как **Редактор**.
7. Перенесите `client_email` в `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `private_key` — в `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`. Ключ поддерживает многострочный PEM либо буквальные `\n` в кавычках.
8. `GOOGLE_SHEET_ID` и `GOOGLE_SHEET_RANGE` должны указывать на ту же таблицу, которую читает витрина. Поддерживаемый диапазон — `'Имя листа'!A1:I1001`, с девятью столбцами из существующей инструкции каталога. Их можно переставлять внутри A:I; переименовывать нельзя.

Вход проверяет подпись Google, issuer, audience, срок, nonce и подтверждённый разрешённый email. Сервисный аккаунт пишет в Sheets через `RAW`, поэтому текст, начинающийся с `=`, не становится формулой. Ключи и токен сервисного аккаунта не возвращаются браузеру.

## Однократная настройка Cloudinary

1. Создайте принадлежащий компании аккаунт с Free планом. Production разрешён в пределах бесплатных квот; это не безлимитное хранилище. Не включайте платные надстройки или автоматическое повышение тарифа ради этой инструкции.
2. Перенесите cloud name, API key и API secret в соответствующие серверные переменные из `.env.example`.
3. Создайте upload preset с режимом **Signed**, запретом unsigned-загрузки, лимитом исходного файла **10 000 000 bytes** и allowlist входных изображений **jpg, jpeg, png, webp, heic, heif**. Значение maximum file size применяется через настройки preset `max_file_size`; форматные ограничения — `allowed_formats`.
4. В preset не задавайте folder, public ID или asset renaming, меняющие public ID. Приложение назначает `inbloom-bouquets/<uuid>`, подписывает `overwrite=false`, преобразование до 2000×2000 и итоговый формат WebP.
5. Сохраните имя в `CLOUDINARY_UPLOAD_PRESET`. Учётная запись должна разрешать серверу чтение метаданных изображений через Cloudinary Admin API. На Free этот API имеет собственную квоту: одна проверка нужна на новую фотографию, а не на просмотр витрины.

Файл загружается с телефона непосредственно в Cloudinary по подписанным параметрам. Затем сервер проверяет ответ и отдельно получает реальные метаданные из Cloudinary: тип, размер, формат, размеры и public ID. Только после этого выдаётся привязанное к сессии разрешение записать фото в таблицу. Секрет Cloudinary остаётся на сервере.

Если формат/preset/преобразование не поддерживаются тарифом или исчерпана квота, загрузка останавливается с сообщением. Покупка или смена тарифа автоматически не выполняются.

## Настройка сервера

Скопируйте `.env.example` в защищённый файл окружения и заполните значения. Для production `SITE_URL` обязателен: точный HTTPS-origin без пути, например `https://example.kz`. `ADMIN_SESSION_SECRET` — случайная строка минимум 32 знака; сгенерировать локально можно `node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"`.

Куки production: host-only, HttpOnly, Secure, SameSite=Lax. Запись требует текущую сессию и точный Origin. Админка/API имеют no-store, noindex и запрет внешнего iframe. Секреты не должны получать префикс `NEXT_PUBLIC_`.

## Ограничения и сохранность

- Первый выпуск: один Node-процесс/экземпляр. Он последовательно выполняет записи и перед изменением перечитывает строку по постоянному ID. Для нескольких экземпляров потребуется общий механизм сериализации; приложение не имитирует его локальной очередью.
- Google Sheets не предоставляет транзакций/compare-and-swap для строк. Прямое одновременное редактирование таблицы остаётся возможным источником гонок. Каталог не является системой приёма заказов или учёта остатков.
- Максимум 1000 строк товаров в текущем диапазоне. Ошибка схемы или дубликат ID блокируют редактирование до исправления; клиентские/внутренние данные в публичный лист каталога не добавляются.
- Встроенного audit trail админки нет; Google сохраняет историю версий таблицы. Перед массовыми ручными правками сделайте копию листа.
- Заменённые и незавершённые фото автоматически не удаляются. Периодически сверяйте папку `inbloom-bouquets` со всеми ссылками в таблице, включая скрытые строки. Перед удалением скачайте копию; не удаляйте используемые или только что загруженные файлы. Это ручная операция владельца, без фонового удаления.
- Для переноса сохраняйте таблицу/доступы, архив фото, исходники и отдельную защищённую копию окружения. Резервная копия VPS не заменяет копии внешних данных.

## Что проверено и что проверить при передаче

Локальные unit-тесты проверяют авторизацию/подписи, проверку фото и запись с подменёнными транспортными ответами. Изолированные браузерные тесты проверяют телефон/desktop, форму, ошибки и повторы; они не записывают данные в настоящий Google/Cloudinary.

Перед коммерческим выпуском отдельно пройдите реальный вход владельца, отказ постороннему аккаунту, загрузку фото с его телефона, создание/изменение/скрытие тестового букета и восстановление данных. Затем проверьте витрину, WhatsApp-текст, HTTPS, перезапуск сервера и восстановление копий. Эти внешние проверки не заменяются успешной локальной сборкой.
