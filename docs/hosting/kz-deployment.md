# In Bloom: хостинг и запуск на .kz

Исследование официальных источников: 28–29 октября 2026. Тариф перед оплатой нужно перепроверить. В этой работе сайт не публиковался, покупка домена/хостинга и изменение DNS не выполнялись.

## Почему зарубежный бесплатный хостинг не выбран

Для домена .kz и его поддоменов KazNIC требует серверы и сетевую инфраструктуру в Казахстане. Зарубежные DNS/почта допускаются, но проксирование иностранного origin не устраняет требование к месту размещения сайта. Требуются действительный HTTPS и перенаправление HTTP на HTTPS. [Разъяснение KazNIC](https://www.nic.kz/docs/reminder_domain_violation.pdf), [проверка Hoster.kz](https://rules.hoster.kz/).

Регистрация домена у hoster.kz не обязывает покупать хостинг там же. Однако подходящего **постоянного бесплатного** казахстанского предложения одновременно для компании, собственного .kz, HTTPS и Next.js/Node.js SSR в ходе проверки подтвердить не удалось. Это результат поиска, а не утверждение, что такой тариф нигде не может появиться. Пробный период не является бесплатной постоянной эксплуатацией.

## Найденные бесплатные альтернативы и их ограничения

- **Netlify Free** разрешает коммерческие проекты, свои домены и HTTPS, поддерживает Next.js SSR. На текущем плане 300 credits/месяц с жёсткой остановкой проектов при исчерпании; расходы включают deploy, трафик, compute и запросы. Подходит для временного показа на служебном домене или международной зоны, но зарубежный origin не выбран для .kz. [Коммерческое использование](https://www.netlify.com/blog/introducing-netlify-free-plan/), [текущий тариф](https://www.netlify.com/pricing/), [учёт credits](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/how-credits-work/), [Next.js](https://docs.netlify.com/build/frameworks/framework-setup-guides/nextjs/overview/).
- **Cloudflare Workers Free**: 100 000 динамических запросов/день, 10 ms CPU на запрос и 128 MB RAM. Совместимость и CPU этого Next.js приложения нужно проверять отдельно; global edge не является подтверждённым origin в Казахстане. [Лимиты](https://developers.cloudflare.com/workers/platform/limits/).
- **Vercel Hobby** предназначен для личного/некоммерческого использования и не подходит для коммерческой витрины магазина. [Условия, раздел 4](https://vercel.com/legal/terms).
- **Websites.kz Basic** действительно имеет 0 ₸, но свой домен начинается на платном тарифе; поддержка постоянного Next SSR не подтверждена. [Тарифы](https://www.websites.kz/sign-up).

## Комплект развёртывания

В репозитории: Dockerfile на Node.js 24, Next standalone build, compose.yaml и Caddy с HTTPS. Отдельной БД/Redis/платной системы входа нет. Этот комплект подготовлен для проверки на VPS, но Docker-сборка и живой сервер должны быть проверены отдельно от локального `next build`.

1. Компания регистрирует нужное имя .kz и приобретает сервер в Казахстане. До покупки подтвердите местоположение, доступ к Docker/Node 24, память и диск, условия резервных копий. Сборка Next может потребовать больше памяти, чем его работа: для 2 GB VPS лучше собирать Linux-образ в CI/на сборочном сервере и доставлять готовый образ, либо проверить сборку и временное увеличение памяти.
2. На сервере установите Docker Engine и Compose plugin по официальной инструкции ОС. Загрузите исходники без локальных секретов и тестовых окружений.
3. Создайте `.env.production` на основе `.env.example`, заполните Google/Cloudinary и `ADMIN_*` по [инструкции админки](../admin/README.md). `SITE_HOST=example.kz`, `SITE_URL=https://example.kz` должны соответствовать реальному имени. Ограничьте чтение окружения владельцем файла.
4. В DNS у Hoster направьте A-записи корня `@` и `www` на реальный IPv4 сервера. AAAA добавляйте только при настроенном IPv6 этого же казахстанского сервера; прежний AAAA на другой сервер мешает доступу/сертификатам. Почтовые MX/TXT оставьте согласно текущему почтовому сервису. [Инструкция Hoster](https://hoster.kz/support/upravlenie-dns-zapisyami-domenov/5581/), [редактирование записей](https://hoster.kz/support/upravlenie-dns-zapisyami-domenov/5537/).
5. Разрешите TCP 80/443 для Caddy. Next.js не публикует порт 3000 наружу: он доступен только Caddy в сети Compose.
6. Выполните `docker compose --env-file .env.production config --quiet`, затем `docker compose --env-file .env.production up -d --build`. Для готового CI-образа замените build на согласованный image и запустите `up -d` после pull. Caddy получает TLS-сертификаты после правильного DNS и доступности портов. Домены в примерах не являются готовой конфигурацией.
7. Проверьте `docker compose --env-file .env.production ps`, HTTP→HTTPS, переход www→корень и сертификат. Убедитесь, что реальные Google origins содержат именно HTTPS-адрес production.
8. Пройдите реальный сценарий из конца инструкции админки. Проверьте публичные /, /catalog и страницу букета, фото, WhatsApp, возврат после перезапуска контейнера и фактическое потребление памяти/CPU. Запишите результат и очистите тестовый товар.

Для запуска без Docker используйте Node.js 24, `npm ci`, `npm run build`, `npm run start`, менеджер одного постоянного процесса и HTTPS reverse proxy. Обычный статический HTML-хостинг не поддерживает эти серверные API. Сборку с Mac нельзя обещать переносимой на Linux из-за нативных зависимостей — собирайте для целевой платформы.

## Передача компании

Домен, сервер, Google Cloud/OAuth, таблица и Cloudinary принадлежат компании. Передаются исходники, доступы через панели сервисов, защищённый файл окружения отдельным каналом, инструкция флористу, перечень периодических расходов, резервные копии таблицы/фото и порядок восстановления. Биллинг, обновления сервера и контроль квот должны иметь ответственного.

Согласованный объём этой реализации не включает оплату, регистрацию домена, изменение DNS, создание внешних аккаунтов или выдачу ключей. Готовность интерфейса и локальных проверок не означает коммерческую публикацию.
