# Однократное подключение Google Таблицы

Google Таблица создана, заполнена и подключена к локальному сайту. В Google Cloud включён Sheets API; отдельный ключ In Bloom catalogue ограничен только Google Sheets API и хранится в игнорируемом `.env.local` с правами 600. Живые изменения цены, добавление и скрытие тестового букета проверены; тестовая строка очищена и исходная цена восстановлена. Шаги ниже нужны для переноса на другой сервер.

1. В Google Cloud выберите проект, включите **Google Sheets API**.
2. Создайте API key с именем **In Bloom catalogue**. Ограничьте доступ API только **Google Sheets API**. Этот ключ читает публичные таблицы, он не даёт право редактировать таблицу. Не используйте чужой существующий ключ.
3. В корне проекта создайте игнорируемый `.env.local` на основе `.env.example`. Заполните `GOOGLE_SHEET_ID=1_c3LU0bGnlkpPgSp6WXUTSe0mId_WjArSk4Keg5pK0k` и `GOOGLE_SHEETS_API_KEY`. Ключ не должен начинаться с `NEXT_PUBLIC_`, попадать в Git, переписку или скриншоты.
4. В новой таблице лист называется **Каталог**. Включите просмотр по ссылке как «Читатель». Публиковать таблицу через «Опубликовать в интернете» не нужно: такой опубликованный файл Google может обновлять с задержкой в несколько минут.
5. Перезапустите Next.js после настройки окружения. При размещении сайта добавьте эти же переменные в секреты хостинга и выполните новое развёртывание.
6. Откройте `/api/catalog`: успешный ответ содержит `source: "sheets"`, `status: "ok"`. Ключ в ответе отсутствует. Ошибки конфигурации/прав/таблицы возвращают 503 и пустой список, без подмены локальными товарами.
7. Для живой проверки запомните цену одного букета, измените её в Google Таблице и убедитесь, что каталог, страница букета и текст WhatsApp обновились. Затем восстановите правильную цену. Измерьте задержку отдельно; тест с заглушкой не доказывает скорость реального Google.

## Как работает обновление

Сервер запрашивает `spreadsheets.values.get` с `UNFORMATTED_VALUE` и `cache: no-store`; JSON-ответ сайта также запрещает browser/CDN-кэш. Короткий кэш процесса — 2 секунды, параллельные запросы объединяются. Открытая страница проверяет каталог каждые 5 секунд; после ошибки — увеличивает интервал до 60 секунд, а при фокусе, возврате в сеть или ручном повторе проверяет немедленно. Обновляются все товары, карточки и именные ссылки WhatsApp.

Это небольшой каталог: до 1000 строк за один запрос. Google ограничивает чтение 300 запросами в минуту на проект и 60 на пользователя в проекте. При большом количестве серверных инстансов нужен общий кэш/контроль квоты: кэш одного процесса не объединяет разные инстансы. Абсолютное обещание «всегда за 10 секунд» недостоверно при ограничении квоты, сбоях Google и сети. Без JavaScript доступна серверная версия каталога на момент запроса; автоматическое обновление требует JavaScript.

Хостинг для коммерческого запуска в этой работе не выбран. API-ключ, публичный домен и успешная синхронизация Google — отдельные проверяемые этапы, их нельзя заменять зелёной локальной сборкой.
