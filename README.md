# In Bloom — цветы в Астане

Адаптивная витрина по утверждённому макету `design/inbloom-landing-v3`: выбор букета, обращение к флористу через WhatsApp, шаги заказа, FAQ и контакты студии.

## Запуск

Нужны Node.js 24 LTS и npm. Версия указана в `.nvmrc`; при использовании nvm выполните `nvm install` и `nvm use`.

```sh
npm ci
npm run dev -- --hostname 127.0.0.1 --port 3000
```

Откройте [локальный сайт](http://127.0.0.1:3000). В текущей среде Node.js 24 установлен дополнительно в игнорируемую `.tooling/node24`; перед командами можно выполнить:

```sh
export PATH="$PWD/.tooling/node24/node_modules/node/bin:$PATH"
```

Шрифты Prata для заголовков и Commissioner для основного текста подключены через `next/font/google`: загружаются при первой сборке, а посетителям выдаются самим приложением. Для первой сборки нужен доступ к Google Fonts. Папка проекта имеет пробел в конце имени — при переходе через терминал заключайте полный путь в кавычки.

Production-режим:

```sh
npm run build
npm run start -- --hostname 127.0.0.1 --port 3001
```

Успешный `build` и локальный preview не означают публикацию в интернете. Для хостинга нужен совместимый Next.js / Node.js runtime. Домен и аккаунт хостинга в проект не добавлены.

## Проверки

```sh
npm test
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
```

Playwright запускает локальный dev-сервер, если он ещё не работает. Для проверки уже запущенной production-версии:

```sh
PLAYWRIGHT_BASE_URL=http://127.0.0.1:3001 npm run test:e2e
```

Тесты проверяют WhatsApp-сообщения и цены, меню, клавиатуру, кнопки витрины, границы списка, изменение ширины, reduced motion, контакты, отсутствие JavaScript и ошибки загрузки изображений. WhatsApp-сообщения не отправляются; внешние назначения проверяются по ссылкам. Визуальные снимки сохраняются в игнорируемой `.frontend-workbench/inbloom-runtime/`. Фактические результаты описаны в `docs/qa/inbloom-runtime.md`.

## Настройки и структура

- `src/config/site.ts` — контакты, внешние ссылки и навигация.
- `src/features/catalog/data.ts` — шесть букетов. Цена хранится числом в тенге; форматирование находится в `format-price.ts`.
- `src/features/catalog/types.ts` — стабильные ID/slug и контракт товара.
- `src/features/contact/whatsapp.ts` — общий запрос и сообщение конкретного букета.
- `src/features/catalog/` — карточки и витрина; серверная страница получает данные через `getFeaturedBouquets()`.
- `src/features/landing/` — первый экран, индивидуальная композиция и шаги заказа.
- `src/features/landing/faq-data.ts` — вопросы и ответы; `faq-accordion.tsx` — взаимодействие, `faq.tsx` — раздел страницы.
- `src/components/` — навигация, подвал и общие элементы.
- `src/app/globals.css` — общие токены и оформление; сложная композиция hero и витрины хранится в CSS modules.

Структура совместима с shadcn: общие компоненты находятся в `src/components/ui`, а alias `@/components/ui` ведёт в эту папку через `tsconfig.json`. Отдельная папка `components/ui` в корне не нужна: она создала бы второй набор компонентов вне существующего alias. `components.json` задаёт пути для CLI, `src/lib/utils.ts` содержит `cn()` на clsx + tailwind-merge. Tailwind CSS 4 и TypeScript уже установлены. Для добавления следующих компонентов можно использовать `npx shadcn@latest add <имя>`; повторный `init` не требуется. [Настройка существующего Next.js-проекта](https://ui.shadcn.com/docs/installation/next), [назначение components.json](https://ui.shadcn.com/docs/components-json).

Раздел «Как заказать» — переключаемая инструкция по новому референсу: три круга, соединительные линии и пояснения первых двух шагов со ссылкой на витрину или WhatsApp. Третий шаг сохраняет номер и краткую подпись; дополнительный текст и ссылка удалены. Состояние выбора принадлежит нативной группе radio; CSS `:has()` управляет панелью и декоративными отметками предыдущих шагов. Переключение работает мышью, клавиатурой и без JavaScript, на телефоне шаги идут вертикально. Это инструкция, её отметки не означают отправку или подтверждение заказа. Новые зависимости не добавлены.

`src/components/ui/3d-card.tsx` адаптирует предоставленный компонент InteractiveTravelCard на `framer-motion`. Увеличенные карточки показывают фото без внешней рамки и внутреннего паспарту, с локальным затемнением под текстом. Внутри остаётся одна ссылка заказа, стрелки и видимые счётчики убраны. Витрина сохраняет нативный Scroll Snap: три карточки на desktop, две на tablet, одна на телефоне; внешние стрелки листания сдвигают ленту справа налево. Поддерживаются клавиатура, возврат наклона и reduced motion, скрытое озвучивание позиции для screen reader. Ссылки WhatsApp доступны без JavaScript. Автоматического перелистывания нет. [Motion values](https://motion.dev/docs/react-motion-value), [reduced motion](https://motion.dev/docs/react-use-reduced-motion).

`src/components/ui/accordion.tsx` адаптирует присланный Radix Accordion: single/collapsible, управление стрелками и Home/End, анимация высоты и поворот шеврона. На странице открывается один ответ; без JavaScript доступны нативные `<details>`. Tailwind 4 использует CSS-first настройку: `accordion-down/up` объявлены в `@theme inline` в `src/app/globals.css`, отдельный `tailwind.config.js` не нужен. Общая настройка reduced motion отключает эти анимации. [Radix Accordion](https://www.radix-ui.com/primitives/docs/components/accordion), [анимации Tailwind](https://tailwindcss.com/docs/animation).

Для FAQ 18 октября 2026 года проверены карточки магазина в 2ГИС, Wolt и публичный каталог Florax. Адрес, контакт и способы оплаты подтверждены открытыми источниками. Тарифы доставки, предоплата, возвраты и точный недельный график магазина не установлены: FAQ предлагает согласовать условия с флористом и открыть график в 2ГИС. Часы доставки Wolt не используются как часы работы магазина. Источники и границы подтверждённых сведений: `docs/assets/shop-research.json`.

Скопируйте `.env.example` в `.env.local` только при необходимости. `SITE_URL` задаёт реальный абсолютный публичный адрес сайта: из него формируются canonical и абсолютные Open Graph URL. Для локального preview оставьте значение пустым. При смене адреса пересоберите приложение. Секреты в этом проекте не требуются, `.env.local` не попадает в Git.

## Контакты и карта

В `src/components/layout/site-footer.tsx` находятся адрес, телефон, кнопки WhatsApp и Instagram, карта и ссылка «Открыть в 2ГИС». Кнопка WhatsApp использует общий `buildWhatsAppLink()`, Instagram ведёт в профиль магазина. FAQ больше не содержит вводную фразу и отдельную кнопку обращения.

`src/config/site.ts` задаёт URL карточки магазина и iframe официального сервиса `widgets.2gis.com`. Формат `firmsonmap` и параметры `pos`, `opt`, `org` соответствуют [официальному загрузчику виджета](https://widgets.2gis.com/js/DGWidgetLoader.js). ID магазина — `70000001105801781`, координаты взяты из ссылки маршрута этой карточки 2ГИС. Виджет начинает загружаться вместе со страницей, содержит собственные обозначения и атрибуцию провайдера; адрес и внешняя ссылка доступны отдельно. Ключ API, сторонний SDK и новые npm-зависимости не требуются. Рендеринг содержимого iframe зависит от доступности сервиса 2ГИС в браузере посетителя.

## Данные и изображения

**Это демонстрационная версия для проверки дизайна. Перед коммерческой публикацией владелец должен подтвердить цены, контакты, ассортимент и разрешение на использование материалов.** На сайте нет обещаний наличия, времени или бесплатной доставки.

Сохранённые материалы содержат цены: Cloud — 18 700 ₸, White bloom — 13 200 ₸, Soft s — 10 700 ₸, Sophie basket S — 12 100 ₸. Для Green red — 20 300 ₸ и Autumn — 15 400 ₸ использован публичный [каталог студии](https://app.florax.kz/ru/in_bloom/bouquets), проверенный 18 октября 2026 года. Данные не синхронизируются автоматически; наличие и условия заказа клиент уточняет у флориста.

Первый экран использует существующую прозрачную вырезку `public/images/bouquets/soft-s.png`: CSS perspective, мягкое покачивание, реакция на курсор и тень создают эффект объёма. Позади неё падают декоративные розовые лепестки. Это слои с 3D-эффектом, а не интерактивная 3D-модель. При reduced motion движение отключается; за пределами экрана анимация сцены приостанавливается. WhatsApp возвращён к обычной кнопке с тонкой светлой границей, без зелёной подсветки. Основные кнопки реагируют на hover и клавиатурный фокус.

Исходная сцена `public/images/hero.png` сохранена и используется для Open Graph. Она и нижняя цветочная композиция — декоративные производные утверждённых макетов, подготовленные Built-in ImageGen без текста и кнопок. Логотип подготовлен из исходного изображения бренда. Четыре букета — ранее сгенерированные прозрачные вырезки из прототипа, скопированные без изменений; это не оригинальные необработанные товарные фотографии. Происхождение, SHA-256 и промпты: `docs/assets/inbloom-assets.json`, `docs/assets/image-prompts.json`, `prototype/assets-receipt.json`. Лицензии шрифтов OFL находятся в `public/licenses/`.

Обновлённые карточки используют пять оригинальных фотографий из публичного каталога студии, сохранённых без обработки в `public/images/catalogue/`, и существующую вырезку Soft s. Ссылки на источники и SHA-256 — в `docs/assets/catalogue-photos.json`. Исходные вырезки сохранены.

## Дальнейшее развитие

Первая версия открывает WhatsApp с подготовленным текстом; отправляет его сам посетитель. Корзина, онлайн-оплата, аккаунты, админка, сохранение заказов и остатки пока не реализованы.

Данные отделены от карточек: локальный источник можно заменить CMS или PostgreSQL, сохранив контракт товара. Полный каталог получит страницы по slug, а корзина и оформление заказа — отдельные модули. На этапе оплаты понадобятся серверная проверка цены и доступности, состояния заказа и интеграция платёжного провайдера.

## Зависимости разработки

На момент первоначальной установки `npm audit --omit=dev` не выявил уязвимостей production-зависимостей. Полный audit сообщает пять high-записей по одной цепочке `eslint-config-next → fast-glob → micromatch → braces`. Для [upstream-проблемы braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) исправленная версия не опубликована. Это инструмент разработки; приложение не передаёт ему данные посетителей. Автоматический downgrade ESLint-конфига до другого major Next.js не применялся. Перепроверяйте audit при обновлении зависимостей.
